# 2026-09-03 工作日志

## A2A 接入调研与设计（OpenClaw + Hermes）

### 实测结论（SSH 探活 101）
- 两端点均为官方原生 **A2A v1.0（JSON-RPC over HTTP）**，Agent Card 均返回 200：
  - OpenClaw：官方 `stock:a2a` 插件 v2026.8.2，JSON-RPC 挂 `http://192.168.123.101:18789/a2a/v1`，`capabilities.streaming=false`（**不支持流式**）
  - Hermes：官方内置（v0.20+），JSON-RPC 挂 `http://127.0.0.1:9900/`，`capabilities.streaming=true`
- 关键差异：JSON-RPC 挂载路径不同（`/a2a/v1` vs `/`）→ 必须从 Agent Card `supportedInterfaces[].url` 取，不可硬编码；流式能力不同 → 驱动必须双路径（streaming=true 走 SendStreamingMessage SSE，false 走 SendMessage+GetTask 轮询）。

### 项目现状
- 适配层现有驱动：`hermes` / `openclaw-ws`（Gateway WS 设备签名）/ `openclaw-cli`（easyclaw CLI）/ `opencode`，**无 a2a 驱动**。
- `AgentKind` 硬编码 `'openclaw'|'hermes'|'opencode'`，出现在 4 处：`server/src/types.ts`、`routes/connections.ts`（z.enum）、`db/schema.ts`（SQLite CHECK 约束）、`web/src/stores/connections.ts`。

### 决策（已与用户确认）
- D1：**新增独立 `kind='a2a'`**（一套驱动接所有 A2A 端点，框架无关）。
- D2：**先出设计、暂不写码**。
- 产出：`A2A-DESIGN.md`（项目根，设计评审稿）。

### 后续落地要点（写码时必看）
- DB CHECK 约束坑：`migrate()` 只跑 `CREATE TABLE IF NOT EXISTS`，改 CHECK 对已存在表不生效，需重建表或移除 CHECK（推荐移除，kind 校验交 zod）。
- 驱动注册点：`server/src/index.ts` 的 `main()` 内 `registerDriver(...)`。
- OpenClaw 认证用 outbound token、Hermes 用 bearer token，统一走 `auth.type='token'`。
- A2A 无能力文件推送语义，push/pull/diff/delete 返回 unsupported，listCapabilities 只读编目 Agent Card skills[]。
- 已确认 A2A v1.0 canonical 方法：SendMessage / SendStreamingMessage / GetTask / ListTasks / CancelTask / SubscribeToTask。
